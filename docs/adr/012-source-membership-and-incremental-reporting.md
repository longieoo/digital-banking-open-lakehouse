# Source membership, change capture and release reuse

A pinned Bronze snapshot includes retained versions. Filtering history by business date can admit an old posting after the source deletes it or moves it outside the requested interval. Each new certified release therefore records the exact primary key and UTC source version of each row returned by the paged source transaction. Preparation writes one private JSONL file per table and pins its SHA-256 and row count. Spark joins against these identities and checks cardinality before transforming. The shared Bronze tables keep their original history. Pre-existing releases use their original procedure.

Silver compares membership with the last published certified release. Reuse requires matching Spark application digest, identical membership, unchanged reference parents and a pinned Silver snapshot. Each candidate still owns its own Iceberg tables. Changed tables undergo full validation. This skips conformance work on unchanged tables while still scanning membership and copying rows. The Spark driver and workers in this Compose deployment share the local runtime path.

For compatible reporting bounds and dbt code, the daily transaction mart compares the complete projected transaction facts in both directions. It aggregates changed days, including the old day of moved or removed transactions, and copies previous results for other days. Other Gold models run normally. The baseline SQL schemas must remain immutable and accessible to the transformer. A new release ID with `python -m scripts.run_release --full-refresh` supplies an independent reference. Compare all exports as unordered row multisets with `python -m scripts.compare_releases LEFT RIGHT --root runtime/releases`.

PostgreSQL row triggers also record committed inserts, updates and deletes in a transactional outbox. Seed installs triggers after the initial load. To migrate an existing database, run `docker compose run --rm --entrypoint python bank -m bank.cdc install`. Installation requires the source schema owner. The archive command `docker compose run --rm --entrypoint python bank -m bank.cdc drain` writes immutable before/after events to the configured raw store. Airflow DAG `bank_cdc_archive` drains bounded batches. Per-event acknowledgments prevent a late commit with a lower sequence ID from being lost. Use one writable primary per origin UUID. Restored clones need separate raw storage. Capturing begins at installation and covers row DML on the declared source tables. Schema changes and TRUNCATE require separate procedures. Certified reports use the consistent source read, while the raw CDC archive preserves intermediate changes.

## Operations

- Benchmark a new dedicated source and stack with `python -m benchmarks.release --customers 400 --transactions 10000`. Optional `--subnet` selects an unused private IPv4 Docker subnet. The result records actual posting count, stage durations, database counters and Docker machine capacity under the generated runtime directory.
- Run `docker compose run --rm spark processing/compact.py --table transactions` in a quiet window. This rewrites eligible Bronze files and compares the complete old and new row multisets. Snapshot expiration remains a separate retention decision.
- Stop writers and the selected project. Run `python -m scripts.cold_backup backup --project PROJECT --runtime RUNTIME --bundle BACKUP` followed by `restore --project NEW_PROJECT --runtime NEW_RUNTIME --bundle BACKUP`. Supply the matching private environment file separately. The trusted backup contains private data. Start the restored services with the new project and runtime and verify PostgreSQL, catalog, objects and consumer state. The bundle covers present core, broker and Airflow volumes and the runtime directory. Spark dependency caches are rebuilt. A partial restore must be retried in a new destination.
- Install Playwright and Chrome locally for `python -m scripts.browser_acceptance --token-file runtime/secrets/http-token`. The test signs in, opens the four pages at two viewport sizes, checks JavaScript and layout overflow, captures screenshots and signs out.
- The hosted storage job exercises PostgreSQL, MinIO and Iceberg on pushes. A dedicated runner can run the distributed workflow manually or weekly when the repository variable `BANK_DISTRIBUTED_CI` is set to `true`.

Fresh installs build MinIO and mc from the upstream commits behind the previously pinned tags. Their Docker Hub images no longer resolve on a fresh runner. The first build downloads the Go toolchain image and module dependencies.
